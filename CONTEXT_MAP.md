# Context Map

| Context | Type | Owns | Relationship |
| --- | --- | --- | --- |
| Edge Contract | Supporting | Versioned generic active configuration, explicit single-upstream authority, request-body budget, timeout/TLS invariants | Upstream of generic Startup/Activation and Pingora Delivery; active v1 remains one-upstream-per-process |
| Edge Routing | Supporting characterization | Deterministic exact/prefix path selection among explicitly named upstream identities, precedence and fail-closed ambiguity | Consumer-derived shared-edge contract; transport-neutral; consumed by the migration callback |
| HTTP Policy | Supporting characterization | Explicit edge-owned HTTP response field identity/value contracts and fail-closed validation | Separate from Edge Routing and product response semantics; transport-neutral; consumed by the migration callback |
| Ingress Forwarding Policy | Supporting | Trust transition from accepted downstream transport/request authority to legacy compatibility forwarding fields | Removes request-controlled proxy identity before rebuilding only characterized `X-Forwarded-*`/`X-Real-IP` values; owns no identity/auth/product truth |
| Migration Plan | Supporting composition | Explicit migration upstream-authority set plus validated Edge Routing and HTTP Policy | Transport-neutral prerequisite for migration delivery; does not grant network authority |
| Migration Delivery | Generic adapter | One-to-one binding from admitted migration upstream identities to explicit validated Pingora peers | Downstream of Migration Plan and `UpstreamConfig`; rejects missing/duplicate/undeclared authority |
| Admin Config | Application/Supporting | Strict pg-erd migration profile version, listener/metrics sockets, runtime budgets, exact `backend`/`frontend` transport bindings | Compiles route/header/upstream-name semantics instead of accepting them from operator input; materializes Pingora peers once before listener activation |
| Runtime Isolation | Supporting | Non-zero request-body and process in-flight admission budgets | Shared by `GatewayProxy` and `MigrationGatewayProxy`; independent of routing/product policy |
| Observability | Supporting | Low-cardinality request completion observation, gateway counters and payload-free access-log shape | Shared by both Pingora adapters; excludes paths, headers, cookies, credentials, customer payloads and product identifiers |
| Startup/Activation | Application | Explicit `--config` path, file loading, validation-before-listen and process composition | Generic binary activates Edge Contract + `GatewayProxy`; pg-erd migration binary activates only `PgErdMigrationConfig` + `MigrationGatewayProxy` |
| Pingora Delivery | Generic adapter | `HttpPeer`, proxy callbacks, health response, forwarding distrust, streamed-body enforcement | Conformist to Pingora, downstream of admitted edge contracts |
| Migration Callback | Generic adapter | `MigrationGatewayProxy` composition of characterized routing/HTTP policy, explicit peer binding, transport-derived forwarding trust, runtime isolation and shared observability | Listener-capable only through the bounded pg-erd composition root; no shadow/canary/cutover claim without traffic evidence |
| Consumer Product | External bounded context | Product routes and semantics, static behavior, authentication/authorization, business policy, domain state | Supplies legacy-edge behavior for characterization where responsibility is truly shared; never imported here |
| Wardnet / EgressWeave | External security contexts | Security verdicts and canonical network/security policy owned there | Referenced boundary only; not reimplemented in HTTP Policy or forwarding trust |
| Keyverse | External identity context | Canonical identity/credential authority | Referenced boundary only; not reimplemented here |
| Certificate Management | External operational context | Issuance, renewal, storage, rotation | Supplies trust material/platform TLS as appropriate; not owned by this runtime |

The generic active v1 shared kernel remains the public one-upstream configuration vocabulary. `edge_routing`, `http_policy`, `migration_plan`, `forwarding_policy`, and `runtime_isolation` are executable migration/supporting contracts. `migration_delivery` binds characterized stable identities to explicit Pingora peers, while `migration_proxy` composes those bindings in `ProxyHttp` callbacks, derives the current pg-erd compatibility forwarding fields from accepted transport metadata, and delegates transport telemetry to `observability`.

`migration_admin` is deliberately not a general multi-route language. It admits deployment-variable socket, runtime-budget and concrete transport/TLS values while fixing the characterized pg-erd route/header/upstream-name contract in code. `from_yaml` performs pure authority validation and does not preload custom trust-bundle bytes; peer/trust materialization occurs once during `build_proxy` before the separate `cwl-pingora-pg-erd-migration` binary creates listeners. The existing `cwl-pingora-gateway` binary and `GatewayConfig` v1 semantics stay unchanged.

The currently characterized pg-erd entryPoint is clear-text `web`; TLS-derived forwarding scheme is a later listener/TLS contract and is not inferred here. Source-level listener capability is not parity, deployment, shadow/canary, cutover or legacy-removal evidence. There is no shared Rust product-domain model with consumer products, Context Graph, Enterprise Architecture, Wardnet/EgressWeave, or Keyverse.
