# Context Map

| Context | Type | Owns | Relationship |
| --- | --- | --- | --- |
| Edge Contract | Supporting | Versioned active configuration, explicit upstream authority, request-body budget, timeout/TLS invariants | Upstream of Startup/Activation and Pingora Delivery; active v1 remains one-upstream-per-process |
| Edge Routing | Supporting characterization | Deterministic exact/prefix path selection among explicitly named upstream identities, precedence and fail-closed ambiguity | Consumer-derived shared-edge contract; transport-neutral; consumed by the pre-listener migration callback |
| HTTP Policy | Supporting characterization | Explicit edge-owned HTTP response field identity/value contracts and fail-closed validation | Separate from Edge Routing and product response semantics; transport-neutral; consumed by the pre-listener migration callback |
| Migration Plan | Supporting composition | Explicit migration upstream-authority set plus validated Edge Routing and HTTP Policy | Transport-neutral prerequisite for migration delivery; does not grant network authority |
| Migration Delivery | Generic adapter | One-to-one binding from admitted migration upstream identities to explicit validated Pingora peers | Downstream of Migration Plan and `UpstreamConfig`; rejects missing/duplicate/undeclared authority |
| Runtime Isolation | Supporting | Non-zero request-body and process in-flight admission budgets | Shared by active `GatewayProxy` and pre-listener `MigrationGatewayProxy`; independent of routing/product policy |
| Observability | Supporting | Low-cardinality request completion observation, gateway counters and payload-free access-log shape | Shared by both Pingora adapters; excludes paths, headers, cookies, credentials, customer payloads and product identifiers |
| Startup/Activation | Application | `--config` parsing, file loading, validation-before-listen, process composition | Currently activates v1 Edge Contract + `GatewayProxy`; multi-route Admin Config/startup transition remains a separate migration slice |
| Pingora Delivery | Generic adapter | `HttpPeer`, proxy callbacks, health response, forwarding distrust, streamed-body enforcement | Conformist to Pingora, downstream of admitted edge contracts |
| Migration Callback | Generic adapter | `MigrationGatewayProxy` composition of characterized routing/HTTP policy, explicit peer binding, runtime isolation and shared observability | Pre-listener only; no shadow/canary/cutover claim until Startup/Activation explicitly admits it |
| Consumer Product | External bounded context | Product routes and semantics, static behavior, authentication/authorization, business policy, domain state | Supplies legacy-edge behavior for characterization where responsibility is truly shared; never imported here |
| Wardnet / EgressWeave | External security contexts | Security verdicts and canonical network/security policy owned there | Referenced boundary only; not reimplemented in HTTP Policy |
| Keyverse | External identity context | Canonical identity/credential authority | Referenced boundary only; not reimplemented here |
| Certificate Management | External operational context | Issuance, renewal, storage, rotation | Supplies trust material/platform TLS as appropriate; not owned by this runtime |

The active v1 shared kernel is the public versioned configuration vocabulary. `edge_routing`, `http_policy`, `migration_plan`, and `runtime_isolation` are executable migration/supporting contracts. `migration_delivery` binds characterized stable identities to explicit Pingora peers, while `migration_proxy` now composes those bindings in `ProxyHttp` callbacks and delegates transport telemetry to `observability`. That does **not** activate multi-route production traffic: the current startup composition still selects `GatewayProxy`. A later versioned Admin Config / startup transition must explicitly admit multi-route serving and then prove parity, shadow/canary, rollback, and cutover evidence. There is no shared Rust product-domain model with consumer products, Context Graph, Enterprise Architecture, Wardnet/EgressWeave, or Keyverse.
