The later public-construction regression `b34bb3a7b0f607e17960815649f55891f8c8ae5e` exposed a distinct Admin Config authority defect. `PgErdMigrationConfig` derives public Serde `Deserialize`, but `build_proxy()` trusted `RuntimeIsolationLimits::from_validated` on the assumption that every value had entered through `PgErdMigrationConfig::from_yaml`. Direct deserialization could therefore construct a zero body or in-flight budget and call the public activation method without the deterministic validation performed by `from_yaml`. Hosted CI `34160430930` reached exact checkout and Rust 1.98.0 formatting, then failed in `test 101860994644` during compile/test on the new direct-deserialization regression; `load-contract` and `oci-runtime` were independently GREEN. This was a real source RED, not a runner or workflow failure.

Minimal production repair `4b468db45fca4bf69302bed4a2449a68a667735a` adds `self.validate()?` at the public `build_proxy()` boundary before peer delivery and the infallible `RuntimeIsolationLimits::from_validated` reuse. This closes the whole deterministic direct-deserialization bypass—version, listener authority, body/in-flight budgets, keepalive and transport-authority invariants—rather than special-casing only the two newly tested zero budgets. It does not change route precedence, HTTP policy, TLS semantics, forwarding identity, product authority, dependency pins or acceptance thresholds. Exact compare from the RED head is one commit, ahead 1 / behind 0, modifying only `src/migration_admin.rs` by three added lines.

The exact source-fix run `34160879253` on `4b468db...` acquired hosted runners. At the evidence snapshot used for this documentation update, exact checkout, Rust 1.98.0 formatting, compile/test, strict Clippy, warning-denied rustdoc, load-contract and OCI runtime had succeeded; the 100% coverage tail and Supply Chain `34160879256` were still executing.
