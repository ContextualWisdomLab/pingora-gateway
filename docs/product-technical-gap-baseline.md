## Authority and bounded contexts

`pingora-gateway` owns shared Ingress, Edge Routing, TLS consumption, HTTP Policy, Load Balancing mechanics, Observability, Admin Config and Runtime Isolation behavior that is genuinely edge/runtime responsibility. Product authentication and business logic remain product-owned. Keyverse remains identity authority; Wardnet/EgressWeave remain their policy authorities. The gateway consumes released/versioned contracts or explicit operator transport inputs and does not copy sibling source, issue cross-service SQL, or depend on mutable sibling PR heads.

Generic v1 remains a one-upstream Rust/Pingora process. The bounded `cwl-pingora-pg-erd-migration` process is a separate composition root for the characterized `pg-erd-cloud` route/header contract; it is not a general product-routing DSL. `PgErdMigrationConfig` deliberately denies unknown fields and admits only concrete listener, runtime budget and characterized `backend`/`frontend` transport bindings. Route authority stays compiled into the migration plan rather than becoming operator-configurable product routing.

### `#21` post-header partial-response phase

This phase owns the characterized backend contract that declares `Content-Length: 20`, commits only the seven-byte `partial` prefix, waits until that prefix has been observed downstream, then closes. Acceptance preserves the committed 200/framing rather than inventing a second status or failover, requires `/readyz` 200, an exact single request-error Prometheus sample, and an independent `frontend` recovery request. The framing oracle parses field lines semantically, matches `Content-Length` case-insensitively, trims field-value whitespace, requires exactly one value equal to `20`, and rejects lookalike or duplicate/conflicting fields. #21 has terminal exact-head CI/Supply Chain evidence; descendants must independently revalidate.

### `#27` recursive gateway network-authority separation

This phase prevents operator-configured upstream transport authority from aliasing either gateway-owned listener. Generic `GatewayConfig` and bounded `PgErdMigrationConfig` reuse one `socket_authorities_overlap` model for exact addresses, IPv4/IPv6 wildcard aliases, IPv4-mapped IPv6 aliases and the conservative IPv6-wildcard/IPv4 dual-stack case. An upstream that aliases the public traffic listener fails with `UpstreamListenerCollision`; one that aliases the internal metrics listener fails with `UpstreamMetricsListenerCollision`. Distinct concrete IP authorities on the same port remain configurable, so the invariant prevents recursive self-proxying and accidental metrics exposure without becoming product routing policy.

The child ordinarily/non-force adopted final #25 with a two-parent ancestry commit whose resolution tree was exactly the final #25 tree, then reapplied only the shared production invariant, bounded migration-admin use of that invariant, and dedicated current-parent acceptance. `tests/network_authority_self_loop_contract.rs` proves generic and pg-erd exact/wildcard/dual-stack collision rejection, distinct-concrete same-port admission, public `build_proxy` revalidation after direct deserialization, and compiled fail-closed startup for both composition roots. The final #27 head has terminal CI/Supply Chain and a fresh technical review with no actionable source/documentation defect; descendants must independently revalidate rather than transfer those receipts.

### `#29` HTTP/1 protocol-transition admission

WebSocket and other connection-wide HTTP/1 Upgrade semantics are not admitted by generic v1 or the bounded pg-erd contract. The current child is ordinarily/non-force based on final #27 with that parent as its exact merge base and no parent-behind debt. A transport-neutral `protocol_transition_policy` treats either an `Upgrade` field or a case-insensitive comma-delimited `upgrade` token in any `Connection` field value as an attempted protocol transition, while rejecting false matches such as `x-upgrade`.

Both Pingora composition roots call the shared delivery guard after gateway-local health handling but before request admission and any route/upstream selection; that is the source-ordering contract. The admitted v1 behavior is HTTP 501 fail-closed, not partial WebSocket support. `tests/protocol_transition_traffic.rs` exercises both compiled listeners with WebSocket-shaped HTTP/1.1 requests, requires exact 501, then observes each dedicated origin listener for a fixed 500 ms post-response window and fails if any connection appears during that window; `/readyz` must remain 200. Its fixture holds traffic/metrics listener reservations concurrently, bounds each response header by a five-second whole-header deadline and 64 KiB, and parses only exact case-sensitive HTTP/1.1 three-digit status tokens so port reuse, slow-drip headers, protocol-case changes or numeric-prefix statuses cannot manufacture GREEN. The 500 ms oracle is deliberately bounded evidence and is not described as proof that an arbitrarily delayed origin connection could never occur.

The first current-parent hosted execution proved OCI and both generic/routed load paths while failing only at the Rust 1.98.0 formatter gate in the new transport-neutral policy regression. Formatter-only repair changes no gateway semantics. A subsequent technical review found the traffic/source distinction above was overstated in documentation; the code-current wording now separates source ordering from the bounded 500 ms wire observation. The changed exact head must complete its own CI/Supply Chain and current-range technical review before #29 can be treated as technically closed. WebSocket enablement requires a separate versioned contract, supplier disposition, handshake/tunnel concurrency, disconnect/backpressure/drain evidence, and distinct HTTP/2 Extended CONNECT handling; removing the v1 rejection alone is not an admissible implementation.
