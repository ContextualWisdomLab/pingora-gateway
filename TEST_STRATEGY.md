# Test Strategy

Tests are organized by bounded responsibility and traffic phase rather than by implementation layer. Source presence is never GREEN evidence by itself: the same exact head must pass formatting, compilation, clippy, warning-denied rustdoc, owned-production 100% line/region coverage, applicable security/supply-chain checks, OCI, and load lanes before release or migration credit is assigned.

## Shared edge contract and startup

`tests/config_contract.rs` proves strict parsing, mandatory positive request/concurrency/keepalive budgets, baseline Edge Contract invariants, and effective network-authority separation between the traffic listener, metrics listener, and admitted upstream. It covers exact collisions, same-port wildcard aliases, conservative IPv6-wildcard/IPv4 dual-stack ambiguity, and valid distinct-concrete same-port authorities. `tests/trust_bundle_contract.rs` proves additional TLS trust-path invariants. `tests/startup_contract.rs`, `tests/binary_startup.rs`, and `tests/trust_bundle_startup.rs` prove fail-closed generic startup, including listener/upstream self-loop rejection before server activation.

`tests/pingora_peer_adapter.rs` proves TLS identity, explicit trust-bundle loading failures, timeout mapping, and Pingora hop-by-hop policy mapping. `tests/peer_protocol_policy.rs` separately locks the protocol-transition invariant at the immutable transport boundary: every peer built through public `build_peer()` must use `HttpUpstreamRequestPolicy::deny_upgrades()` rather than Pingora's default `WebSocketOnly` mode. This is defense in depth beneath request admission and prevents later callback/composition refactors from silently widening the admitted protocol surface. `tests/gateway_proxy.rs` proves admitted config produces the expected peer, missing trust material blocks activation, forwarding identity is sanitized, and process-local admission capacity fails closed and recovers. `tests/runtime_policy.rs` locks one total upstream attempt, the configured keepalive-pool budget, and bounded shutdown policy.

`tests/production_path.rs` drives the generic compiled binary through a real loopback Pingora listener and local origin. It covers health, declared and streamed/chunked 413 body rejection, post-rejection readiness, forwarding sanitization, normal proxy response, and saturation: one held in-flight request consumes a one-request budget, the next application request must fail fast with 503, `/readyz` remains available, rejection telemetry advances, and capacity recovers after release. On Unix, `tests/local_ca_tls.rs` generates a short-lived local CA/server certificate, proves explicit trust works, then changes only SNI and requires hostname verification to fail closed. `tests/graceful_shutdown.rs` holds a request in flight, sends SIGTERM, requires that response to drain inside the configured grace period, and requires clean process exit before the external supervisor hard-kill budget.

## Protocol-transition admission

`tests/protocol_transition_policy.rs` is the transport-neutral RED→GREEN contract for the current HTTP/1 protocol boundary. Ordinary HTTP and unrelated `Connection` tokens such as `x-upgrade` remain admitted. Any `Upgrade` field is transition evidence, and an ASCII case-insensitive `upgrade` token in any comma-delimited `Connection` field value is also transition evidence, including mixed case and multiple field values.

`tests/protocol_transition_traffic.rs` then proves the policy through both compiled composition roots. It sends a WebSocket-shaped HTTP/1 request to generic v1 and to a characterized pg-erd `/api` path, requires HTTP 501, verifies that no generic origin, pg-erd backend, or pg-erd frontend socket was contacted, and requires gateway-local `/readyz` to remain available. Together with `tests/peer_protocol_policy.rs`, this proves both the application admission boundary and the lower transport peer agree that HTTP/1 Upgrade is denied. These tests intentionally prove rejection rather than WebSocket success. The current PRD has no WebSocket policy, and fresh supplier evidence has open `cloudflare/pingora#946` with proposed fix `#947` still unmerged. A later WebSocket version must add its own handshake/tunnel, concurrency/race, disconnect, backpressure, drain, and supplier-disposition evidence; HTTP/2 Extended CONNECT and HTTP/3 remain separate contracts.

## Bounded pg-erd characterization and activation

`tests/pg_erd_route_contract.rs` freezes the observed Traefik route precedence, including literal raw `/api` prefix behavior. `tests/pg_erd_http_policy_contract.rs` freezes the separately owned response-security fields and values, case-insensitive field identity, absent lookup, duplicate-field rejection, empty/invalid name/value rejection, and CR/LF injection rejection. `tests/pg_erd_migration_plan_contract.rs`, `tests/pg_erd_upstream_binding_contract.rs`, `tests/pg_erd_forwarding_contract.rs`, and `tests/pg_erd_runtime_proxy_contract.rs` prove the transport-neutral plan, exact upstream binding, forwarding-trust boundary, response-policy composition, and shared runtime-isolation/observability callback behavior.

The bounded Admin Config transition is separately executable. `tests/pg_erd_admin_config_contract.rs` rejects unknown/future configuration, traffic/metrics listener collision, zero runtime/keepalive budgets, missing/extra/duplicate/renamed authority, invalid concrete transport configuration, and any characterized `backend`/`frontend` transport authority that overlaps the gateway's traffic or metrics listener under the shared exact/wildcard/dual-stack semantics. `tests/pg_erd_binary_startup.rs` exercises the dedicated compiled process and requires fail-closed behavior for omitted/unreadable configuration, invalid Admin Config, custom TLS trust material that cannot be materialized before listener activation, and listener/upstream self-loop before network activation.

`tests/pg_erd_production_path.rs` starts real loopback `backend` and `frontend` origins plus `cwl-pingora-pg-erd-migration`. Gateway-local `/livez` and `/readyz` remain local, consumer `/healthz` and raw `/apiary` reach `backend`, fallback product traffic reaches `frontend`, hostile forwarding identity is discarded and rebuilt from accepted loopback transport/Host evidence, an upstream `X-Frame-Options: SAMEORIGIN` is replaced by characterized `DENY` together with the other response fields, and an over-limit declared body fails with 413 before origin delivery.

`tests/pg_erd_runtime_isolation_traffic.rs` adds chunked overflow and in-flight saturation/recovery. `tests/pg_erd_upstream_failure_traffic.rs` covers connection refusal: HTTP 502 within the connection budget, healthy readiness, low-cardinality error telemetry, and independent fallback recovery. `tests/pg_erd_read_stall_traffic.rs` covers an accepted connection that emits no response bytes: the configured per-read `read_ms` inactivity budget must fail as 502 within a conservative outer bound, without transferring evidence to slow-drip or whole-response lifetime behavior.

`tests/pg_erd_partial_response_traffic.rs` covers the orderly post-header phase: the backend commits HTTP 200 plus `Content-Length: 20`, sends only `partial`, then closes. The downstream must preserve the committed status/framing and terminate incomplete rather than receiving a second status or silent failover; readiness, error telemetry, and an independent route remain usable. On Linux, `tests/pg_erd_upstream_reset_traffic.rs` covers a real pre-header TCP RST using `SO_LINGER(0)`, requiring prompt 502 without failover or waiting for the read inactivity budget. `tests/pg_erd_post_commit_reset_traffic.rs` moves the same abortive close past downstream response commitment and requires the already-committed response boundary to be preserved. These tests characterize ordinary HTTP failure phases; they do not provide WebSocket or generic long-lived-stream support.

`tests/pg_erd_payload_free_observability.rs` sends unique URI/query, Host, Authorization, Cookie, and product-context sentinels through a real routed request. The backend must receive the values so the fixture is non-vacuous, while the canonical `cwl_pingora_gateway::observability` target emits only bounded status/outcome/request-body facts and no sentinel. This proves the CWL-owned access-log vocabulary independently from product-owned logging.

`tests/pingora_diagnostic_log_safety.rs` covers the process-wide dependency boundary that the shared access-log test cannot prove. It starts the compiled generic runtime with operator `RUST_LOG=trace`, sends URI/query/Authorization/Cookie sentinels that the origin must actually receive, waits for the normal bounded completion record, and then requires none of those sentinels anywhere in process stderr. The corresponding production logging policy preserves operator-selected levels/targets but replaces every Pingora-family dependency record message with a static marker before formatting. This prevents supplier diagnostics from bypassing the payload-minimization contract without claiming authority over consumer/product loggers.

On Unix, `tests/pg_erd_graceful_shutdown.rs` holds a characterized `/api/held` request at the backend, sends SIGTERM only after the backend received it, releases the response inside the shared grace period, requires downstream HTTP 200, and requires the migration process to exit successfully inside the external termination budget.

## OCI and load evidence

The OCI gate builds one digest-pinned distroless image and exercises both composition roots as uid/gid 65532 with a read-only root filesystem, all Linux capabilities dropped, `no-new-privileges`, and read-only configuration mounts. Generic v1 remains the default entrypoint; pg-erd is selected explicitly and must expose its process-health and metrics listeners. Source acceptance is not deployment evidence until the unchanged exact-head OCI job executes terminal-success.

`tests/load/gateway_smoke.js` runs checksum-pinned k6 2.2.0 against the release-mode generic binary and a deterministic std-only Rust HTTP/1.1 origin built as `examples/load_origin.rs`. The fixture reads its port and fixed payload once at startup, prebuilds the response bytes, enables `TCP_NODELAY`, preserves HTTP/1.1 keep-alive, and emits no per-request logs; no Python interpreter or stdlib HTTP server remains in the measured round trip. The generic contract sends 400 requests across four VUs, requires the expected status/body, zero failed requests, and loopback `http_req_duration` p95 below 20 ms. `tests/load/pg_erd_gateway_smoke.js` separately exercises `cwl-pingora-pg-erd-migration` with two instances of the same Rust fixture as distinct backend/frontend authorities; 400 requests across four VUs alternate characterized backend and fallback routes and require route-specific bodies, zero failures, and the same local p95 bound. Startup probes establish readiness only and do not pre-exercise measured application routes. These remain local regression bounds, not production SLO evidence, until the exact-head load job executes and representative TLS/network/origin-capacity/deployment measurements exist.

## Migration and release evidence still missing

Every legacy migration begins with behavior characterization and then equivalent Pingora production-path evidence. Static-serving consumers must cover applicable route precedence, SPA fallback, MIME, ETag/cache, Range/HEAD/304/416, redirects/security fields, and compression. Proxy consumers must cover Host/SNI/TLS, forwarding trust, request limits, timeout/retry behavior, streaming/uploads, saturation/backpressure, errors, health/readiness, drain, and process-wide payload-safe diagnostics. WebSocket/Upgrade is a separate versioned capability and cannot be inferred from a supplier feature flag or a lightly loaded happy-path test.

Release-quality gaps remain: no downstream TLS listener contract; no HTTP/2 or HTTP/3 parity; no tracing evidence; no slow-drip/whole-response lifetime control; no representative origin-capacity/TLS/network/multi-hop/container-orchestrator benchmark; no immutable published registry digest/provenance with rehearsed rollback; no shadow/canary/cutover/legacy-removal evidence; and no benchmark against the replaced Nginx/Traefik production path. Supplier/security/dependency blockers remain fail-closed. All source acceptances, including protocol-transition rejection, peer-level Upgrade denial, dependency-diagnostic redaction, and the Rust-origin latency lane, must be reacquired on the exact final head after any source or documentation movement.
