# Test Strategy

Tests are organized by responsibility rather than by implementation layer.

`tests/config_contract.rs` proves strict parsing, mandatory positive request/concurrency/keepalive budgets, and baseline Edge Contract invariants. `tests/trust_bundle_contract.rs` proves the additional TLS trust-path invariants. `tests/startup_contract.rs` proves explicit fail-closed startup. `tests/pingora_peer_adapter.rs` proves TLS identity, explicit trust-bundle loading failures, timeout, and Pingora hop-by-hop policy mapping. `tests/gateway_proxy.rs` proves admitted config produces the expected peer, missing trust material blocks activation, and the process-local admission budget fails closed and releases capacity. `tests/runtime_policy.rs` locks the no-retry, configured upstream keepalive-pool, and bounded-shutdown process policy. `tests/binary_startup.rs` and `tests/trust_bundle_startup.rs` exercise compiled-process startup failures. `tests/production_path.rs` drives the compiled binary through a loopback Pingora listener and real local HTTP upstream fixture, covering health, declared and streamed/chunked 413 body-limit rejection, post-rejection readiness recovery, forwarding-identity sanitization, proxy response, and an executable saturation contract: with one in-flight lease held upstream, the next application request must fail fast with 503, `/readyz` must remain available, the rejection counter must advance, and a later request must succeed after the lease is released. `tests/pingora_diagnostic_log_safety.rs` runs the compiled gateway with `RUST_LOG=trace`, proves URI/query, Host, Authorization, and Cookie sentinels reach the origin unchanged, requires a post-request Pingora redaction marker, and rejects those sentinels anywhere in process stderr so dependency diagnostics cannot bypass the payload-minimization boundary. On Unix, `tests/local_ca_tls.rs` generates a short-lived CA/server certificate at test time, proves the compiled gateway can trust that explicitly mounted CA, then changes only SNI and requires hostname verification to fail closed. On Unix, `tests/graceful_shutdown.rs` holds a request in flight, sends SIGTERM, proves the response drains during the configured grace period, and requires clean process exit before the external supervisor hard-kill budget. Real-listener process fixtures retain their ephemeral traffic/metrics reservations through configuration construction, then acquire one shared cross-process `tests/support::StartupLock` before releasing those reservations; the lock is held only through child bind plus bounded readiness/listener confirmation so a different integration-test process cannot steal the handoff window. The diagnostic-log fixture follows the same handoff contract rather than relying on scheduler timing. `tests/startup_lock_contract.rs` proves that the shared guard is an operating-system-owned exclusive file lock, a competing handle cannot acquire it while the owner lives, owner drop releases it, and dropping an older already-unlocked handle cannot release a successor lock. Acquisition remains bounded; descriptor/process close releases ownership without stale-directory deletion or an mtime lease, and the test guard adds no runtime/Cargo dependency.

`tests/toolchain_contract.rs` makes compiler selection part of release acceptance after Rust 1.98.1 fixed the vtable-generation miscompilation in 1.98.0. Every CI or Supply Chain job that executes host `cargo` must install, select, and verify Rust 1.98.1 inside that same job before its first and every later Cargo command; repository/workflow toolchain overrides and any selector introduced after verification fail the contract rather than inheriting compiler state from a sibling job or runner image. `tests/compiler_wrapper_authority_contract.rs` independently rejects Cargo compiler rebinding through `RUSTC`, `RUSTC_WRAPPER`, `RUSTC_WORKSPACE_WRAPPER`, their `CARGO_BUILD_*` configuration-environment equivalents, or `RUSTUP_TOOLCHAIN` at workflow/job/step YAML scope, in shell assignments, and in Docker `ENV`, `ARG`, shell-form `RUN`, or JSON-form `RUN` instructions; it also keeps repository `.cargo/config.toml` / `.cargo/config` out of the release path until such configuration receives an explicit compiler-authority contract. The OCI contract separately requires the Docker builder to install, select, and verify 1.98.1 before its sole `cargo build`, with no later selector before compilation. While Docker Official Image lacks a 1.98.1 Bookworm tag, the digest-pinned 1.98.0 builder image is only a bootstrap environment and must not compile the gateway itself. Crate metadata independently rejects Rust 1.98.0.

`tests/load/gateway_smoke.js` is a separate concurrent traffic contract executed with checksum-pinned k6 2.2.0 against the release-mode gateway binary and `tests/load/upstream_fixture.py`, a deterministic local HTTP/1.1 upstream. Before measured traffic starts, the CI load lane requires both its bounded application-level `/readyz` polling check and its final `/readyz` validation to return exact HTTP 200 and verifies `Cache-Control: no-store`; `/livez` alone is not accepted as readiness evidence. No readiness check runs after measured traffic. The contract sends 400 requests across four virtual users, requires every response to preserve the expected status/body, requires zero failed HTTP requests, and gates loopback `http_req_duration` p95 below 20 ms. Its gateway fixture supplies explicit downstream in-flight and upstream keepalive-pool budgets rather than relying on Pingora framework defaults. This is a regression bound for the minimal local gateway path, not evidence that an Internet, TLS, multi-hop, or consumer production path satisfies a 20 ms p95 SLO. Each real migration must measure its representative path, load shape, connection reuse, TLS, upstream latency, CPU/RSS and failure behavior before adopting that target.

Every behavioral migration should begin with characterization against the old owned edge behavior, then add equivalent production-path evidence for Pingora. Static-serving consumers must cover route precedence, SPA fallback, MIME, ETag/cache, Range/HEAD/304/416, redirects/security headers and compression as applicable. Proxy consumers must cover Host/SNI/TLS, forwarding trust, WebSocket/upgrade, limits, timeout/retry behavior, streaming/uploads, saturation/backpressure, errors, health/readiness and drain.

Release-quality gaps remain: no property/fuzz tests yet; no downstream TLS listener contract; no HTTP/2 or HTTP/3 parity evidence; no tracing evidence; no immutable published registry digest/provenance and rehearsed rollback; and no benchmark against replaced Nginx/Traefik traffic. The in-flight request budget is executable, but there is not yet a representative consumer-specific queue/concurrency/origin-capacity study proving chosen production values. OCI non-root/read-only-root, owned-production 100% line/region coverage, public rustdoc, private production rustdoc through `clippy::missing_docs_in_private_items`, SBOM/image vulnerability, local-CA upstream TLS, explicit backpressure/recovery, payload-safe dependency diagnostics, and the minimal k6 loopback path have executable gates or tests, but each must still be terminal-success on the exact release candidate. The private-rustdoc restriction is disabled under `cfg(test)` so test helpers do not distort the owned-production documentation gate. Recovery after streamed body rejection and refused-origin connection is covered; broader reset/slow-stream/network-failure recovery is not. Production performance claims remain forbidden until representative deployment measurements exist.
