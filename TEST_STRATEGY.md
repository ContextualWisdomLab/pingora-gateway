# Test Strategy

Tests are organized by responsibility rather than by implementation layer.

`tests/config_contract.rs` proves strict parsing and baseline Edge Contract invariants. `tests/trust_bundle_contract.rs` proves the additional TLS trust-path invariants. `tests/startup_contract.rs` proves explicit fail-closed startup. `tests/pingora_peer_adapter.rs` proves TLS identity, explicit trust-bundle loading failures, timeout, and Pingora hop-by-hop policy mapping. `tests/gateway_proxy.rs` proves admitted config produces the expected peer and that missing trust material blocks activation. `tests/runtime_policy.rs` locks the no-retry and bounded-shutdown process policy. `tests/binary_startup.rs` and `tests/trust_bundle_startup.rs` exercise compiled-process startup failures. `tests/production_path.rs` drives the compiled binary through a loopback Pingora listener and real local HTTP upstream fixture, covering health, declared and streamed/chunked 413 body-limit rejection, post-rejection readiness recovery, forwarding-identity sanitization, and proxy response. On Unix, `tests/local_ca_tls.rs` generates a short-lived CA/server certificate at test time, proves the compiled gateway can trust that explicitly mounted CA, then changes only SNI and requires hostname verification to fail closed. On Unix, `tests/graceful_shutdown.rs` holds a request in flight, sends SIGTERM, proves the response drains during the configured grace period, and requires clean process exit before the external supervisor hard-kill budget.

Every behavioral migration should begin with characterization against the old owned edge behavior, then add equivalent production-path evidence for Pingora. Static-serving consumers must cover route precedence, SPA fallback, MIME, ETag/cache, Range/HEAD/304/416, redirects/security headers and compression as applicable. Proxy consumers must cover Host/SNI/TLS, forwarding trust, WebSocket/upgrade, limits, timeouts/retries, streaming/uploads, errors, health/readiness and drain.

Release-quality gaps remain: no property/fuzz tests yet; no downstream TLS listener contract; no HTTP/2 or HTTP/3 parity evidence; no realistic concurrency/backpressure/load evidence; no tracing evidence; no immutable published registry digest/provenance and rehearsed rollback; and no benchmark against replaced Nginx/Traefik traffic. OCI non-root/read-only-root, owned-production 100% line/region coverage, public rustdoc, SBOM/image vulnerability, and local-CA upstream TLS have executable gates or tests, but each must still be terminal-success on the exact release candidate. Recovery after streamed body rejection is covered; broader upstream/network failure recovery is not. Performance claims are forbidden until representative latency/throughput/CPU/RSS/connection-reuse/TLS measurements exist.
