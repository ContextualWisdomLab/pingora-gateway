# Test Strategy

Tests are organized by bounded responsibility and traffic phase rather than by implementation layer. Source presence is never GREEN evidence by itself: the same exact head must pass formatting, compilation, clippy, warning-denied rustdoc, owned-production 100% line/region coverage, applicable security/supply-chain checks, OCI, and load lanes before release or migration credit is assigned.

## Shared edge contract and startup

`tests/config_contract.rs` proves strict parsing, mandatory positive request/concurrency/keepalive budgets, baseline Edge Contract invariants, and effective network-authority separation between the traffic listener, metrics listener, and admitted upstream. It covers exact collisions, same-port wildcard aliases, conservative IPv6-wildcard/IPv4 dual-stack ambiguity, and valid distinct-concrete same-port authorities. `tests/trust_bundle_contract.rs` proves additional TLS trust-path invariants. `tests/startup_contract.rs`, `tests/binary_startup.rs`, and `tests/trust_bundle_startup.rs` prove fail-closed generic startup, including listener/upstream self-loop rejection before server activation.

`tests/pingora_peer_adapter.rs` proves TLS identity, explicit trust-bundle loading failures, timeout mapping, and Pingora hop-by-hop policy mapping. `tests/peer_protocol_policy.rs` separately locks the protocol-transition invariant at the immutable transport boundary: every peer built through public `build_peer()` must use `HttpUpstreamRequestPolicy::deny_upgrades()` rather than Pingora's default `WebSocketOnly` mode. This is defense in depth beneath request admission and prevents later callback/composition refactors from silently widening the admitted protocol surface. `tests/gateway_proxy.rs` proves admitted config produces the expected peer, missing trust material blocks activation, forwarding identity is sanitized, and process-local admission capacity fails closed and recovers. `tests/runtime_policy.rs` locks one total upstream attempt, the configured keepalive-pool budget, and bounded shutdown policy.

`tests/production_path.rs` drives the generic compiled binary through a real loopback Pingora listener and local origin. It covers health, declared and streamed/chunked 413 body rejection, post-rejection readiness, forwarding sanitization, normal proxy response, and saturation: one held in-flight request consumes a one-request budget, the next application request must fail fast with 503, `/readyz` remains available, rejection telemetry advances, and capacity recovers after release. On Unix, `tests/local_ca_tls.rs` generates a short-lived local CA/server certificate, proves explicit trust works, then changes only SNI and requires hostname verification to fail closed. `tests/graceful_shutdown.rs` holds a request in flight, sends SIGTERM, requires that response to drain inside the configured grace period, and requires clean process exit before the external supervisor hard-kill budget.

## Parked HTTP/1 read shutdown gap

The existing graceful-drain tests exercise admitted in-flight work and do not close `pingora-gateway#46`. At protected public Pingora `09696b51bc59315353d96686355861604d0bb48c`, each `HttpProxy` instance can park the HTTP/1 reads it handles against that instance's shared `tokio::sync::Notify`; upstream #844 reports severe waiter-list contention under 128-core keep-alive load and public PR #969 is still unmerged. Independent #969 review reproduces the separate lost-wakeup race on that public main when shutdown occurs before waiter registration. The contributor PR branch is not test input or dependency authority.

#46 RED must run against the exact compiled generic and bounded pg-erd composition roots. Establish many new and reused keep-alive connections whose HTTP/1 sessions are parked waiting for a request, then jitter SIGTERM around the transition where `read_request()` is pending and the shutdown waiter is registering. The affected supplier revision must demonstrate at least one parked-read survivor without reducing the configured production grace. A separate high-concurrency run must characterize registration/unregistration overhead with realistic configured workers and parked connections; capture shutdown wall time, CPU utilization, and Linux off-CPU/futex evidence when available. Do not reduce worker/connection counts, turn off keep-alive, or use a low-core pass to claim that the #844 contention is absent.

#46 GREEN requires an immutable/released maintainer-integrated Pingora capability or separately governed provenance-bound backport. Repeat the race under adversarial jitter and concurrency and require zero parked-read survivors beyond the bounded shutdown expectation. In the same acceptance, hold already-admitted application requests across SIGTERM and require them to retain existing graceful completion semantics inside the configured grace, then require successful process exit, startup/recovery sanity, and correct `/livez`/`/readyz` behavior. If the supplier repair uses sharding, profile the actual configured worker/runtime topology rather than assuming host `available_parallelism()` is the worker count. Request paths, headers, cookies, credentials and customer payloads are unnecessary and must not enter this evidence.

## Downstream HTTP/1 header admission and lifetime gaps

No current source test is credited as GREEN for either supplier-bound downstream header control. #43 / `cloudflare/pingora#993` owns parser-phase byte/count admission below Pingora's fixed H1 ceilings. #45 / `cloudflare/pingora#447` separately owns the elapsed lifetime of one incomplete H1 request header. A semantic rejection after `RequestHeader` construction cannot satisfy the first, and a per-read inactivity timeout cannot satisfy the second.

The #45 RED must use a real downstream HTTP/1 socket against a compiled composition root and send an incomplete header in small fragments at intervals below the current per-read inactivity timeout. Traffic must stay below the desired byte/count ceiling so an eventual failure cannot be attributed to #43. The observation must show that the request can remain in header acquisition beyond a deliberately smaller whole-header budget without reaching application request callbacks. Reused keepalive and pipelined-prefix cases must be included when the supplier capability exposes those paths. A later GREEN must terminate the in-progress header at a monotonic overall budget despite continued partial progress, preserve normal/idle requests, keep process health available, avoid logging attacker header contents, and leave an independent characterized route usable. Test-only timing may be scaled, but shrinking a global read timeout or relying on a retained Nginx/Traefik layer is not equivalent evidence.

## Protocol-transition admission

`tests/protocol_transition_policy.rs` is the transport-neutral RED→GREEN contract for the current HTTP/1 protocol boundary. Ordinary HTTP and unrelated `Connection` tokens such as `x-upgrade` remain admitted. Any `Upgrade` field is transition evidence, and an ASCII case-insensitive `upgrade` token in any comma-delimited `Connection` field value is also transition evidence, including mixed case and multiple field values.

`tests/protocol_transition_traffic.rs` then proves the policy through both compiled composition roots. It sends a WebSocket-shaped HTTP/1 request to generic v1 and to a characterized pg-erd `/api` path, requires HTTP 501, verifies that no generic origin, pg-erd backend, or pg-erd frontend socket was contacted, and requires gateway-local `/readyz` to remain available. Together with `tests/peer_protocol_policy.rs`, this proves both the application admission boundary and the lower transport peer agree that HTTP/1 Upgrade is denied. These tests intentionally prove rejection rather than WebSocket success. The current PRD has no WebSocket policy, and fresh supplier evidence has open `cloudflare/pingora#946` with proposed fix `#947` still unmerged. A later WebSocket version must add its own handshake/tunnel, concurrency/race, disconnect, backpressure, drain, and supplier-disposition evidence; HTTP/2 Extended CONNECT and HTTP/3 remain separate contracts.

## Bounded pg-erd characterization and activation

`tests/pg_erd_route_contract.rs` freezes the observed Traefik route precedence, including literal raw `/api` prefix behavior. `tests/pg_erd_http_policy_contract.rs` freezes the separately owned response-security fields and values, case-insensitive field identity, absent lookup, duplicate-field rejection, empty/invalid name/value rejection, and CR/LF injection rejection. `tests/pg_erd_migration_plan_contract.rs`, `tests/pg_erd_upstream_binding_contract.rs`, `tests/pg_erd_forwarding_contract.rs`, and `tests/pg_erd_runtime_proxy_contract.rs` prove the transport-neutral plan, exact upstream binding, forwarding-trust boundary, response-policy composition, and shared runtime-isolation/observability callback behavior.

The bounded Admin Config transition is separately executable. `tests/pg_erd_admin_config_contract.rs` preserves the version-1 characterization contract and rejects unknown/incomplete/future configuration, traffic/metrics listener collision, zero runtime/keepalive budgets, missing/extra/duplicate/renamed authority, invalid concrete transport configuration, and any characterized `backend`/`frontend` transport authority that overlaps the gateway's traffic or metrics listener under the shared exact/wildcard/dual-stack semantics. `tests/pg_erd_response_lifetime_config.rs` covers the opt-in version-2 increment: it requires an explicit positive `max_upstream_response_body_ms`, rejects zero or a missing version-2 value, and proves version 1 cannot silently acquire version-2 timing semantics. `tests/pg_erd_binary_startup.rs` exercises the dedicated compiled process and requires fail-closed behavior for omitted/unreadable configuration, invalid Admin Config, custom TLS trust material that cannot be materialized before listener activation, and listener/upstream self-loop before network activation.

On Unix, `tests/pg_erd_local_ca_tls.rs` separately proves the bounded composition root consumes its admitted upstream TLS contract rather than inheriting generic evidence. It generates an ephemeral one-day local CA and `backend.test` certificate, configures only `backend` as TLS and keeps `frontend` a distinct clear-text authority, then requires characterized `/api` traffic to succeed with matching explicit trust and SNI. A second process keeps the CA valid while changing only backend SNI; the routed backend request must fail as HTTP 502 without route failover, gateway-local `/readyz` must remain 200, and a later fallback request must still reach `frontend`. The fixture proves gateway-to-upstream TLS trust/hostname verification only. It does not claim downstream TLS termination, certificate issuance/rotation ownership, or production-network TLS latency.

`tests/pg_erd_production_path.rs` starts real loopback `backend` and `frontend` origins plus `cwl-pingora-pg-erd-migration`. Gateway-local `/livez` and `/readyz` remain local, consumer `/healthz` and raw `/apiary` reach `backend`, fallback product traffic reaches `frontend`, hostile forwarding identity is discarded and rebuilt from accepted loopback transport/Host evidence, an upstream `X-Frame-Options: SAMEORIGIN` is replaced by characterized `DENY` together with the other response fields, and an over-limit declared body fails with 413 before origin delivery.

`tests/pg_erd_runtime_isolation_traffic.rs` adds chunked overflow and in-flight saturation/recovery. `tests/pg_erd_upstream_failure_traffic.rs` covers connection refusal: HTTP 502 within the connection budget, healthy readiness, low-cardinality error telemetry, and independent fallback recovery. `tests/pg_erd_read_stall_traffic.rs` covers an accepted connection that emits no response bytes: the configured per-read `read_ms` inactivity budget must fail as 502 within a conservative outer bound.

`tests/pg_erd_slow_drip_response_traffic.rs` distinguishes that inactivity contract from the version-2 response-body lifetime. The backend commits HTTP 200 with `Content-Length: 20` and sends one body byte every 60 ms while `read_ms` is 500 ms, leaving substantial scheduling margin so the old per-read timeout cannot be mistaken for the new lifetime. The version-2 config separately declares `max_upstream_response_body_ms: 300`; the gateway must terminate the committed response before all 20 bytes arrive, retain the original committed status rather than inventing a second status/failover, increment request-error telemetry, keep `/readyz` available, and serve a later independent frontend route. The lifetime starts on the first non-informational `upstream_response_filter` callback and is checked on body-progress callbacks. The fixture proves continuous body slow-drip is bounded, not that Pingora can interrupt a pending read at an exact absolute deadline. Slow-drip of an incomplete response header remains outside this test.

`tests/pg_erd_partial_response_traffic.rs` covers the orderly post-header phase: the backend commits HTTP 200 plus `Content-Length: 20`, sends only `partial`, then closes. The downstream must preserve the committed status/framing and terminate incomplete rather than receiving a second status or silent failover; readiness, error telemetry, and an independent route remain usable. On Linux, `tests/pg_erd_upstream_reset_traffic.rs` covers a real pre-header TCP RST using `SO_LINGER(0)`, requiring prompt 502 without failover or waiting for the read inactivity budget. `tests/pg_erd_post_commit_reset_traffic.rs` moves the same abortive close past downstream response commitment and requires the already-committed response boundary to be preserved. These tests characterize ordinary HTTP failure phases; they do not provide WebSocket or generic long-lived-stream support.

`tests/pg_erd_payload_free_observability.rs` sends unique URI/query, Host, Authorization, Cookie, and product-context sentinels through a real routed request. The backend must receive the values so the fixture is non-vacuous, while the canonical `cwl_pingora_gateway::observability` target emits only bounded status/outcome/request-body facts and no sentinel. This proves the CWL-owned access-log vocabulary independently from product-owned logging.

`tests/pingora_diagnostic_log_safety.rs` covers the process-wide dependency boundary that the shared access-log test cannot prove. It starts the compiled generic runtime with operator `RUST_LOG=trace`, sends URI/query/Authorization/Cookie sentinels that the origin must actually receive, waits for the normal bounded completion record, and then requires none of those sentinels anywhere in process stderr. The corresponding production logging policy preserves operator-selected levels/targets but replaces every Pingora-family dependency record message with a static marker before formatting. This prevents supplier diagnostics from bypassing the payload-minimization contract without claiming authority over consumer/product loggers.

On Unix, `tests/pg_erd_graceful_shutdown.rs` holds a characterized `/api/held` request at the backend, sends SIGTERM only after the backend received it, releases the response inside the shared grace period, requires downstream HTTP 200, and requires the migration process to exit successfully inside the external termination budget. This remains in-flight drain evidence only; it is intentionally not reused as #46 parked-read shutdown evidence.

## OCI and load evidence

The OCI gate builds one digest-pinned distroless image and exercises both composition roots as uid/gid 65532 with a read-only root filesystem, all Linux capabilities dropped, `no-new-privileges`, and read-only configuration mounts. Generic v1 remains the default entrypoint; pg-erd is selected explicitly and must expose its process-health and metrics listeners. Source acceptance is not deployment evidence until the unchanged exact-head OCI job executes terminal-success.

`tests/load/gateway_smoke.js` runs checksum-pinned k6 2.2.0 against the release-mode generic binary and a deterministic std-only Rust HTTP/1.1 origin in `tests/load/load_origin.rs`. The fixture is test tooling rather than a Cargo production/example target: the load lane formats and compiles it directly with the pinned Rust 1.98.0 toolchain and `-D warnings`, so it cannot dilute or inflate the owned-production 100% coverage denominator. It reads its port and fixed payload once at startup, prebuilds the response bytes, enables `TCP_NODELAY`, and emits no per-request logs; no Python interpreter or stdlib HTTP server remains in the measured round trip. The generic contract sends 400 requests across four VUs, requires the expected status/body, zero failed requests, and loopback `http_req_duration` p95 below 20 ms. `tests/load/pg_erd_gateway_smoke.js` separately exercises `cwl-pingora-pg-erd-migration` with two instances of the same Rust fixture as distinct backend/frontend authorities; 400 requests across four VUs alternate characterized backend and fallback routes and require route-specific bodies, zero failures, and the same local p95 bound. Startup probes establish readiness only and do not pre-exercise measured application routes.

`tests/load/pg_erd_gateway_capacity.js` is a separate capacity/concurrency regression rather than a replacement for the four-VU baseline. The shared Rust origin now has an explicit positive worker budget capped at 256, a bounded accept queue derived from that budget, a startup-only response service delay, and explicit keep-alive/close behavior. Before k6 starts, `tests/load/run_pg_erd_capacity.sh` proves the fixture itself is non-vacuous: one worker, `Connection: close`, and a 150 ms service delay must serialize two concurrent direct-origin requests into a bounded 250–1500 ms observation window. Measured traffic then starts four-worker `backend` and `frontend` origins with `Connection: close` and a 1 ms service delay, drives the exact release-mode pg-erd binary with 16 VUs / 1600 requests split across both characterized routes, requires exact route bodies plus zero check/HTTP failures, and requires `http_req_duration` p95 below 20 ms for the aggregate sample **and independently for the route-tagged backend and frontend samples**. The summary is uploaded separately under the exact head. This is controlled loopback origin-capacity and connection-churn evidence, not a production origin/network/TLS SLO. No application route is warmed before the measurement.

Both load contracts remain source acceptance until their exact-head jobs execute terminal-success. Representative production-origin capacity, TLS/network/multi-hop/container-orchestrator measurements and comparison with the replaced legacy path remain separate requirements before any production 20 ms p95 claim. The #46 shutdown-contention profile is a different benchmark: it must retain high worker and parked keep-alive connection pressure and measure the supplier synchronization path rather than reuse request-latency k6 results as a substitute.

## Migration and release evidence still missing

Every legacy migration begins with behavior characterization and then equivalent Pingora production-path evidence. Static-serving consumers must cover applicable route precedence, SPA fallback, MIME, ETag/cache, Range/HEAD/304/416, redirects/security fields, and compression. Proxy consumers must cover Host/SNI/TLS, forwarding trust, request limits, timeout/retry behavior, streaming/uploads, saturation/backpressure, errors, health/readiness, drain, and process-wide payload-safe diagnostics. WebSocket/Upgrade is a separate versioned capability and cannot be inferred from a supplier feature flag or a lightly loaded happy-path test.

Release-quality gaps remain: no downstream TLS listener contract; no HTTP/2 or HTTP/3 parity; no tracing evidence; no downstream HTTP/1 whole-request-header slow-drip deadline (#45/#447); no upstream response-header slow-drip deadline (#40/#992); no immutable public supplier/backport evidence plus race/concurrency GREEN for parked HTTP/1 shutdown (#46/#844/#969); no exact timer-interrupt guarantee beyond the combined response-body progress guard plus `read_ms`; no representative production-origin-capacity/TLS/network/multi-hop/container-orchestrator benchmark; no immutable published registry digest/provenance with rehearsed rollback; no shadow/canary/cutover/legacy-removal evidence; and no benchmark against the replaced Nginx/Traefik production path. Supplier/security/dependency blockers remain fail-closed. All source acceptances, including the new pg-erd version-2 response-body lifetime, upstream TLS trust/hostname-failure recovery, protocol-transition rejection, peer-level Upgrade denial, dependency-diagnostic redaction, Rust-origin low-contention latency, and bounded-origin capacity lanes, must be reacquired on the exact final head after any source or documentation movement.
